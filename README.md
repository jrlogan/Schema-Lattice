# SchemaLattice

A permissionless, AI-facing catalog of data model concepts for the wave of
personal apps about to be generated by LLMs.

**Status:** v0.1 in design. Pre-code. Specification complete; implementation
not started.

## The problem

LLM-generated personal apps are about to proliferate. Every one of them will
define its own data models from scratch. When any two of them need to
interoperate — share data, compare records, migrate between tools — they'll
have to renegotiate vocabulary from first principles because nothing in the
current stack gives them a shared substrate to refer to.

Existing work circles the problem from four sides:

- **Enterprise ontologies** (Palantir, Atlan, Galaxy) are centralized and
  single-tenant.
- **Schema.org / linked data** is deliberately centralized and has no
  native fork-and-evolve story.
- **Schema registries** (Confluent, Avro) handle versioning within one
  organization, not across unknown future collaborators.
- **Agent protocols** (MCP, A2A, ANP) standardize *how* agents talk, not
  *what* the fields in their messages mean.

None of them answer the question: when an AI builds your scuba app today
and a different AI builds your friend's underwater-welding app next year,
how can the two apps compare dive histories without either side having
to teach the other what a "dive" is?

## The thesis

We build the missing layer: a forkable, lineage-preserving, AI-facing
catalog of concepts (and the schemas that instantiate them). An AI building
a new app can discover existing concepts, adopt them as-is, fork them with
explicit changesets, or originate genuinely new ones. Every concept carries
a stable content-addressed URI. Every fork carries a structural diff that
future tools can use to translate between apps.

The AI consumes the catalog through an MCP server and follows a small
protocol (see `specs/ai-checkpoints.md`) telling it when to consult the
lattice and how to annotate its output so future tools can trace back.

## What this reuses

SchemaLattice is a composition, not a new ontology system.

- **SKOS** (W3C Simple Knowledge Organization System) for Concept,
  ConceptScheme, labels, and the core semantic and mapping relations.
- **PAV** (Provenance, Authoring, Versioning) for `derivedFrom`,
  `createdBy`, `previousVersion`, `importedFrom`.
- **JSON-LD** `@context` as the canonical serialization — plain JSON on
  the wire, RDF-compatible when the semantic-web tools need it.
- **HTTPS URIs** as identifiers, with content-addressed hashes for
  immutability.
- **Model Context Protocol** for the AI-facing tool interface.

## What this adds

- A permissionless, git-style social protocol for publish and fork.
- A vector discovery layer over concept definitions for AI consumers.
- A lightweight in-code annotation standard (`schemalattice.json` sidecar
  manifests and `[lattice:SHORT_NAME]` inline marker tags) that lets any
  future tool walk from code back to canonical concept definitions.
- An AI checkpoint protocol with six checkpoints across three groups,
  small enough for any LLM to internalize in one skill file.
- A genuinely new relation `:coRefersWith` for "same real-world referent,
  different perspective" — the thing SKOS and PAV don't cover.

## Scope of v0.1

- Single-instance catalog server (Node/TS, SQLite, local embeddings)
- HTTP + MCP interfaces
- Four essential MCP tools: discover, resolve, publish_concept,
  publish_fork (plus optional list_context, stats)
- A Claude skill file encoding the checkpoint protocol
- Local testing first; deploy to `schemalattice.io` later

Deferred to v0.2:

- The `/reconcile` endpoint for bar-scene app-to-app negotiation
- Full Cambria lens layer for bidirectional schema translation
- Multi-instance federation
- Governance / endorsement / social signal
